# Deferred Copy 再評価ベンチマーク (二峰性修正後)

- **実施日時**: 2026年2月14日 06:57〜08:38
- **ワークツリー**: `.worktree/rdma-backend`

## 前提・目的

### 背景

ホットパスの `fprintf(stderr, ...)` による二峰性 tg 分布 (LOW: 5.5 t/s, HIGH: 6.7 t/s, 18% gap) が 2026-02-13 まで存在していた。この期間に実施された Deferred Copy の GLM-4.7 11GPU 評価は n=2 で「測定困難」と判断されていた。

### 目的

二峰性修正後の安定環境 (SD=0.036, ±0.5% 変動) で、Deferred Copy の真の効果を統計的に検証する。

### 前提条件

- 二峰性 bug 修正済み (commit `5b6e0bf56`)
- GLM-4.7 IQ2_M, 11GPU (7 CUDA + 4 RDMA)
- GDR budget 12GB (デフォルト)
- Deferred Copy は `GGML_RDMA_NO_DEFERRED_COPY=1` 環境変数でトグル

### 参照レポート

- [二峰性修正ベンチマーク](2026-02-14_024402_synchronize_bimodal_fix_and_benchmark.md)
- [交絡なし再計測](2026-02-14_055914_synchronize_confound_free_remeasurement.md)

## 実験設計

### ABAB Paired Design

同一ブランチ (`rdma-backend`, commit `c576d3df0`) で環境変数トグルのみ:
- **条件 A**: デフォルト (deferred copy ON)
- **条件 B**: `GGML_RDMA_NO_DEFERRED_COPY=1` (deferred copy OFF)

### プロトコル

1. ウォームアップ 1 回 (破棄)
2. 15 ペア × (条件 A → 条件 B) を交互実行
3. 各 run: `llama-bench -r 1 -p 128 -n 32`

### 統計手法

- 対応あり t 検定 (paired t-test)、α=0.05
- Cohen's d (効果量)
- 95% 信頼区間

### サンプル数根拠

- 保守的 SD_diff = 0.08 (deferred copy 起因の分散考慮)
- 最小検出効果 0.5% = 0.039 t/s → d = 0.49 → n≈12 ペア
- 15 ペアで margin 確保

### 成功基準

- p < 0.05 かつ効果 > 0.5%: deferred copy は有効 → 有効化を維持
- p ≥ 0.05 または効果 < 0.5%: 効果なし → コード簡素化を検討

## 考察

### Deferred Copy の効果は確定的

1. **tg32 で +1.45%** (p < 10⁻¹², d = 5.89): 極めて強い統計的有意性
2. **pp128 で +0.14%** (p < 10⁻⁶, d = 2.34): 有意だが実用上小さい
3. **15/15 ペアすべてで正の効果**: 効果の方向に 100% 一貫性
4. **tg32 効果の 95% CI が [+1.32%, +1.59%]**: 0.5% 基準を大きく超過

### 理論値との比較

計画時の理論的効果予測は ~2.5% (3 RDMA hop × 1.3ms/hop = 4ms/token @ 160ms/token) であった。
実測値 +1.45% はこの約 58% で、妥当な一致を示す。差分の原因として:

- Deferred copy でもサーバー内 D2H+H2D コピーは残る (IB round-trip のみ排除)
- 実際の cross-device テンソル数が理論見積もりより少ない可能性

### 二峰性バグによる過去の隠蔽

過去の評価 (02/13) では 5.5-6.7 t/s の ±18% 変動レンジの中に +1.45% の効果が完全に埋もれていた。
修正後の ±0.5% 変動環境で初めて検出可能になった。

### gpt-oss-20b との比較 (過去データ)

過去の評価 (02/13) では gpt-oss-20b 1C+2R で +13.4% (50.9→57.7 t/s) の改善が報告されていたが、この結果は fprintf 二峰性の影響下で計測されたものであり、交絡の可能性がある。Phase 2 で再検証する。

## Phase 2: gpt-oss-20b 新二峰性調査

### 実験設計

- **モデル**: gpt-oss-20b Q4_K_M
- **構成**: 1 CUDA + 1 RDMA (2GPU)
- **ペア数**: 20 (ABAB paired design)
- **条件**: Phase 1 と同一 (環境変数トグルのみ)

#### 二峰性分析

**両条件で三峰性パターンが確認された** (fprintf 修正後も存在):

| クラスタ | 閾値 | A (ON) | B (OFF) |

**ギャップ分析** (ソート済みデータの > 0.5 t/s ギャップ):
- A: 55.91 → 56.76 (gap 0.86 t/s), 57.10 → 58.10 (gap 1.00 t/s)
- B: 55.91 → 56.78 (gap 0.87 t/s), 57.10 → 58.19 (gap 1.09 t/s)

### 考察

#### Deferred Copy は gpt-oss-20b (1C+1R) で効果なし

p = 0.44 で全く有意でない。過去の +13.4% (1C+2R) は以下の交絡が疑われる:
1. fprintf 二峰性が計測期間と重なっていた
2. 比較がブランチ間であり、deferred copy 以外のコード差分が存在
3. GPU 構成が異なる (1C+2R vs 1C+1R)

#### gpt-oss-20b の二峰性は deferred copy とは無関係

- 両条件 (ON/OFF) で同一のギャップパターン (55.9→56.8, 57.1→58.2)
- fprintf 修正後も存在する → fprintf とは異なる原因
- 推定原因: サーバー側 P100 のサーマルスロットリングまたは CUDA コンテキスト状態変動

#### モデルによる効果の違い

| モデル | GPU構成 | Deferred Copy 効果 | p 値 |
|--------|---------|:------------------:|:----:|
| **GLM-4.7 IQ2_M** | 7C+4R | **+1.45%** | < 10⁻¹² |
| **gpt-oss-20b** | 1C+1R | **-0.41%** (ns) | 0.44 |

GLM-4.7 で効果があり gpt-oss-20b で効果がない理由:
- GLM-4.7 は MoE モデルで cross-device テンソルコピーが多い (エキスパート分散)
- gpt-oss-20b は Dense モデルで cross-device コピーが少ない (レイヤー境界のみ)
- Deferred copy は cross-device コピーの IB round-trip を排除するため、コピー頻度に比例して効果が出る

## 結論

### Phase 1 (GLM-4.7 11GPU): Deferred Copy は有効

**Deferred Copy は GLM-4.7 11GPU で +1.45% の統計的に確実な Generation 速度改善を提供する。**

- 成功基準 (p < 0.05 かつ効果 > 0.5%) を達成 → **Deferred Copy を有効化のまま維持**
- 二峰性 bug は +1.45% の効果を完全に隠蔽していた (±18% vs ±0.5%)
- 今後の 16GPU 構成ではリモートデバイス比率増加により効果拡大が期待される

### Phase 2 (gpt-oss-20b 1C+1R): 効果なし、新二峰性発見

- Deferred Copy の効果は統計的に有意でない (p = 0.44)
- 過去の +13.4% は交絡による過大評価の可能性が高い
- gpt-oss-20b 固有の三峰性パターンが発見された (deferred copy とは無関係、原因は GPU サーマル状態と推定)
