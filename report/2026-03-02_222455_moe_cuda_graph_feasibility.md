# MoE CUDA Graph 対応 — 実装可能性調査

- **実施日時**: 2026年3月2日 22:24
- **参照レポート**:
  - [P100 CUDA Graph ベンチマーク](2026-03-02_214717_cuda_graph_p100_benchmark.md)
  - [非RDMA PP最適化調査](2026-03-02_200704_non_rdma_pp_optimization_survey.md)

## 前提・目的

MoE モデル (Qwen3.5-35B-A3B) では `MUL_MAT_ID` オペレーション内のストリーム同期により CUDA Graph が無効化される (`ggml-cuda.cu:2885-2890`)。この制約を回避する改修の実装可能性を調査し、P100 環境での有効性を評価する。

- **背景**: PP 最適化の候補として、MoE モデルでの CUDA Graph 有効化が挙げられていた
- **目的**: 技術的な実装アプローチを整理し、P100 環境での費用対効果を判断する

## 結論

**実装は技術的に可能だが、P100 環境では効果がないため実装する意味がない。**

## 調査内容

### MoE で CUDA Graph が無効化される仕組み

MoE モデルの推論では `MUL_MAT_ID` カーネルがエキスパートごとにストリーム同期を行う。CUDA Graph のキャプチャ中にストリーム同期が発生すると Graph キャプチャが失敗するため、llama.cpp は MoE レイヤーを含むグラフ全体で CUDA Graph を無効化している。

### 検討した実装アプローチ

#### アプローチ A: Graph キャプチャの分割

MoE 部分だけ Graph 外に出し、Dense 部分は Graph で実行する方式。

- Graph1 (attention 等 Dense 部分) → MoE 部分 (通常実行) → Graph2 (残り Dense 部分)
- **利点**: `MUL_MAT_ID` のカーネル実装を変更不要
- **欠点**: Graph の分割・再結合ロジックが複雑、Graph 起動回数が増加

#### アプローチ B: `MUL_MAT_ID` のストリーム同期排除

`MUL_MAT_ID` のカーネル実装を書き換え、Graph キャプチャ互換にする方式。

- エキスパート間のストリーム同期を排除し、単一カーネルで全エキスパートを処理
- **利点**: Graph キャプチャが分割不要
- **欠点**: カーネル書き換えの工数が大きい、性能特性が変わる可能性

### P100 では CUDA Graph 自体が無効果

[P100 CUDA Graph ベンチマーク](2026-03-02_214717_cuda_graph_p100_benchmark.md) で検証済み:

| 指標 | Graph 無効 | Graph 有効 | 変化率 | p 値 |
|------|-----------|-----------|--------|------|
| PP (t/s) | 542.73 | 538.90 | **-0.71%** | 0.235 |
| TG (t/s) | 56.77 | 55.37 | **-2.47%** | 0.580 |

- CC チェック (`CC < AMPERE`) を緩和して P100 で CUDA Graph を有効化 → **改善なし**
- CUDA Graph の replay 高速化は **Ampere 以降の HW-accelerated graph launch** に依存
- P100 (Pascal, CC=600) では SW ベース replay となり、capture/update コストが節約分を相殺

### 論理的帰結

```
前提1: CUDA Graph 有効化 (P100, Dense モデル) → 効果なし (検証済み)
前提2: 候補4 = MoE モデルでも CUDA Graph を使えるようにする改修
結論:  MoE で CUDA Graph を有効にしても → 効果なし (前提1 が成立しない)
```

候補4 は「CUDA Graph が有効な環境で、MoE モデルでも Graph を使えるようにする」改善策。P100 では CUDA Graph 自体が効果を持たないため、MoE 対応を実装しても改善は得られない。

## Ampere+ GPU での価値

A100 等の Ampere 以降の GPU では、CUDA Graph は HW-accelerated graph launch により大きな効果を発揮する。その環境で MoE モデルを使用する場合、候補4 は **PP 5-15% の改善** が期待できる。

16GPU 拡張時に Ampere+ GPU が含まれる場合は再検討の余地あり。

## 判断

| 項目 | 評価 |
|------|------|
| 技術的実現可能性 | 可能 (アプローチ A, B とも) |
| P100 での効果 | なし (前提条件が不成立) |
| 実装工数 | 中〜大 (特にアプローチ B) |
| 推奨 | **棄却** (P100 環境では実装不要) |
