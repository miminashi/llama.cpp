## 前提・目的

`feature/rdma-backend` ブランチは upstream (`ggml-org/llama.cpp` master) の `05728db18` 時点でマージ済み。upstream が `1e38a7a6f` まで 38 コミット進んでいるため、追従マージを行いデグレがないことを確認する。

- 前回のマージ: [2026-03-06 upstream merge レポート](2026-03-06_222500_upstream_merge_qwen35_pp_opt.md)
- 前回マージ基点: `05728db18`
- 今回マージ先: `1e38a7a6f` (upstream/master)

### 注意すべき upstream 変更

- **`ggml/src/ggml-backend.cpp`** (#17795): split 実行の同期ロジック変更
  - event がない場合の `ggml_backend_synchronize` を split 先頭と compute 直前に移動
  - `ggml_backend_tensor_copy` → `ggml_backend_tensor_copy_async` に変更
  - RDMA バックエンドは event 未実装のため `NULL` パス（synchronize）に入る。動作上の問題なし
- **`ggml/src/ggml-cuda/ggml-cuda.cu`** (#17795): CPU→CUDA async copy 対応、kernel fusion 追加 (ssm_conv+silu, unary+mul)

## 再現方法

### マージ

```bash
git worktree add .worktree/merge-upstream-20260307 -b merge/upstream-20260306 feature/rdma-backend
cd .worktree/merge-upstream-20260307
git fetch upstream
git merge upstream/master --no-edit
```

README.md にコンフリクト発生（RDMA ドキュメント行と Hexagon パス変更の近接）。RDMA 行を保持し、Hexagon パスは upstream (`docs/backend/snapdragon/README.md`) を採用して解決。


## 判定

| 項目 | 結果 |
|------|------|
| **コンフリクト** | README.md のみ（RDMA行 + Hexagon パス変更） — 解決済み |
| **RDMA ファイル影響** | なし（upstream は `ggml-rdma/` に触れていない） |
| **正確性** | Qwen3.5 4GPU で正常な推論出力を確認 |
| **Qwen3.5 pp128** | +0.37% (±2% 以内) — OK |
